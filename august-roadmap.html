WEEK 109:00 – 18:00 전원 통일

네이버 튜토리얼 — 기획 · 실행 교육

물길에는 기획과 실행이 따로 있습니다. 어떤 키워드로 유입을 만들지 정하는 게 기획, 실제로 발행하는 게 실행. 이번 주는 둘 다 배웁니다.

시간 구조

월화수
오전
튜토리얼 — 블로그 · 카페 · 지식인. 물길 기획(키워드 · 후킹 잡는 법)과 물길 실행(발행 실무) 둘 다 민지 · 도희 · 정인
매일
오후
각자 메인퀘스트 — 오전에 배운 걸 자기 파트에 바로 적용
목금
오전
일퀘 도입 — 월화수에 익숙해진 물길을 매일 돌리는 걸로 전환

하는 일

  • 전원 네이버 계정 세팅 완료
  • 블로그 · 카페 · 지식인 각각 첫 발행
  • 골반안정기구 물길 정리해서 실제로 돌려보기 유리
  • 네이버 자동화 툴 개발 착수 의준 — 물길 실행 제외
  • 새로운 R 기획 시작 창민 + 소진
  • 창민이 디코방 순회하며 진행 상태 확인

끝나면 남는 것

  • 개인별 일퀘 역량 수치 — 시간당 몇 개를 하는지. 앞으로의 모든 기준선
  • 새 R 기획 초안 — 2주차에 바로 투입
  • 금요일 리뷰 — 막힌 지점 공유, 2주차 파티 구성 · 근무 시간 확정
배운 걸로 실제 제품을 태운다
WEEK 2파티별 유연 근무 시작

실행 — 기존 R + 새 R + 자동화 툴 테스트

1주차에 창민이 기획한 새 R이 여기서 들어옵니다. 기존 제품으로 익힌 물길을 새 제품에 그대로 얹어보는 주입니다.

시간 구조

시간 1
기존 R 물길 + 자동화 툴 테스트 · 피드백 일퀘
시간 2
새로운 R 물길 + 자동화 툴 테스트 · 피드백 메인퀘
시간 3
사이드퀘 — 있는 사람만. 시간은 각자, 공유는 필수

하는 일

  • 파티 제도 도입 — 2~3인 단위, 비슷한 시간대에 근무
  • 9-6 해제. 타임테이블에 각자 근무 시간 올리기
  • 새 R에 물길 세팅 — 1주차 기획안 그대로 적용
  • 자동화 툴 1차 버전 → 쓰면서 피드백 의준
  • 상세페이지 디자인 템플릿 작업 병행 희정

끝나면 남는 것

  • 새 R 물길 가동 — 유입 데이터 첫 수치
  • 자동화 툴 피드백 목록 — 실제로 써본 사람들의 불편 지점
  • 물길 공식 초안 — 뭐가 먹히고 뭐가 안 먹히는지
내가 하던 걸 남에게 넘긴다
WEEK 3여기가 병목 해소 구간

시스템 구축 — 위임 교육 / 자동화 툴

2주 동안 직접 해봤기 때문에 이제 남을 가르칠 수 있습니다. 내가 계속 붙어 있으면 4주차에 기획할 시간이 없습니다.

하는 일

  • 각자 자기 파트의 프리랜서 관리 · 교육
  • 2주차에 검증된 물길 공식을 프리랜서에게 이관
  • 자동 발행 시스템 구축 — 원고 · 업로드 의준
  • 상세페이지 템플릿 자동화 완성 희정
  • 1주차 역량 수치 기준으로 얼마나 넘길지 결정

끝나면 남는 것

  • 프리랜서 온보딩 자료 — 다음 제품에도 재사용
  • 자동 발행 시스템 가동
  • 비워진 시간 — 4주차 기획에 쓸 여유

이 주가 중요한 이유

  • 이 주를 건너뛰면 5주차부터 사이클이 안 돕니다. 새 R을 기획해도 실행할 손이 없어서요.
  • 넘기는 게 목적이지 완벽하게 넘기는 게 목적은 아닙니다. 70%만 넘겨도 성공.
이제 기획을 직접 해본다
WEEK 4한 주 안에 기획부터 테스트까지

기획 대항전 — 팀별로 R 기획 & 테스트

3주 동안 배운 걸로 각 팀이 R을 하나씩 기획합니다. 발표하고, 피드백 받고, 실제로 물길을 태워서 숫자로 승부를 봅니다.

시간 구조

월
기획 데이 — 팀별로 R 하나 잡고 물길 기획서까지
화
발표 + 피드백 — 창민이 팀별로 피드백, 그 자리에서 수정
수목
물길 테스트 — 기획안 실제로 태워보기
금
결과 리뷰 — 숫자로 판정, 다음에 갈 R 확정

규칙

  • 판정 기준은 월요일에 미리 확정 — 유입수 / 저장·공유율 / 문의수 중에서
  • 기획서에 딸깍인지 관람차인지 먼저 명시
  • 이 주 동안 창민은 별도로 다음 R 기획 진행

끝나면 남는 것

  • 테스트를 통과한 R — 다음 주에 프리랜서로 넘길 것
  • 이긴 물길 포맷 — 앞으로 복제할 공식
  • 각자 기획 경험 1회 — 이게 진짜 산출물

기획 + 실행 + 위임 — 3트랙 안정적으로 돌리기

4주차까지가 준비였고, 여기서부터가 실제로 숫자를 만드는 구간입니다. 세 트랙이 순서대로가 아니라 동시에 돌아갑니다. 이번 주 기획한 게 다음 주 실행으로, 그 다음 주 위임으로 흘러가는 구조예요.
